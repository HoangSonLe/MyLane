# AI Development Workflow

Version: 1.0

This document defines how AI tools should be used throughout the development of Memory Arena.

The objective is to ensure every generated screen, component and feature remains consistent with the project architecture and Design System.

# Step 4 - Claude Production Refactor

Prompt: [Open prompt](ai-prompts.md#step-4---claude-production-refactor)

## Objective

Convert prototype code into production-ready architecture.

---

## Prompt

You are a Senior Frontend Engineer.

Treat the current UI as the visual source of truth.

Preserve:

- layout
- spacing
- hierarchy
- UX
- interactions

Do NOT redesign the interface.

Your tasks are:

1. Extract reusable components.

2. Organize folders.

3. Improve TypeScript.

4. Improve accessibility.

5. Improve semantic HTML.

6. Remove duplicated JSX.

7. Replace hardcoded values.

8. Improve maintainability.

9. Follow the project architecture.

10. Follow the Design System.

Visual changes should be minimal.

Explain every visual change.

## Code Organization Rules

When refactoring generated screens or existing pages, follow these placement rules:

### Components

- Keep page files focused on orchestration.
- If a page contains many local subcomponents, split them into separate files as soon as they have a clear responsibility.
- Prefer folder-per-kit organization instead of one flat UI folder.
- Keep related components together under a dedicated kit folder such as `button/`, `card/`, `layout/`, `controls/`, `grid/`, `form/`, `settings/`, or a feature kit folder like `gameplay/`, `leaderboard/`, `profile/`, `result/`.

### Types and Enums

- Move shared enum-like values into `frontend/src/configs/enum.ts`.
- Do not create many feature-local `enum.ts` files if the values are shared across screens.
- Place feature-specific interfaces in separate files such as `xxx.interface.ts`.

### API and Mock Data

- Place feature API logic in `xxx.api.ts` or in a feature data-layer file when it is clearly not UI code.
- Place mock data in `xxx.mock.ts` or a feature-local `mocks/` folder.
- Do not keep API stubs, mock data, and UI markup in the same page file when the page is already dense.

### Refactor Priority

1. Extract repeated page shell and header patterns.
2. Extract repeated cards, rows, filters, and overlays.
3. Split dense page-local subcomponents into separate files.
4. Move shared enums, interfaces, API helpers, and mocks out of page files.
5. Keep the visual result unchanged unless a minimal fix is required.

Prompt: [Open prompt](ai-prompts.md#step-7---future-screens)

reuse existing components.

## Prompt

Create a new screen using ONLY the existing Design System and reusable components.

Do not introduce

- new colors
- new spacing
- new typography

- new card styles

Maintain complete visual consistency.

# Rules

Never let AI redesign the project automatically.

Never replace the Design System.

Never introduce a second visual language.

Always evolve the existing system.

Prototype first.

Architecture second.

Production third.
